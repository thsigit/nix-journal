*Provider lifecycle commands + sops consolidation*

## 1. Objective

Document the session's work on LiteLLM gateway management: extending litellm-cli with provider lifecycle commands, consolidating sops secrets, fixing broken providers, testing model availability across all providers, and creating persistent OpenCode skills for homelab, AI, and boot management.

## 2. Background

The LiteLLM gateway runs on NixOS via Podman, consuming a rendered `config.yaml` from `litellm-cli`. Provider configuration lives in `gateway.json` (persistent), model inventory in `models.json` (ephemeral, rebuilt each boot), and API keys in `providers.env` (sops-encrypted). This session extends the CLI tooling to manage the full provider lifecycle: adding, removing, blacklisting, and testing models.

## 3. Problem

Three issues needed resolution:

1. litellm-cli lacked commands to remove providers and manage blacklists - operators had to edit `gateway.json` manually.
2. `providers.env` had a trailing space in the `ZAI_API_KEY` value, causing authentication failures through LiteLLM but not via direct curl.
3. `litellm-podman.nix` contained a hardcoded `DATABASE_URL` with a plaintext password, duplicating the credentials already generated by `common/db/default.nix`.

## 4. Work Performed

### 4.1 litellm-cli commands added

| Command | Purpose |
|---------|---------|
| `providers remove <name>` | Remove a provider from gateway.json |
| `providers blacklist <provider> <model>` | Add model to provider's blacklist |
| `providers unblacklist <provider> <model>` | Remove model from blacklist |
| `providers blacklists [provider]` | Show all blacklists or one provider's |
| `models fetch <provider>` | Query provider's /v1/models endpoint |
| `models --text-only` | Filter: text input + text output only |
| `models --embeddings` | Filter: embedding models |
| `models --reranking` | Filter: reranking models |
| `models --vision` | Filter: image or video input |
| `models --audio` | Filter: audio input/output |
| `models --video` | Filter: video input/output |
| `models --image-gen` | Filter: image generation |

Capability filters use additive OR logic and filter against the `models.json` inventory's `modalities.input`/`modalities.output` fields from models.dev.

### 4.2 Sops secrets consolidation

Merged `litellm.env` into `providers.env`:

| Before | After |
|--------|-------|
| `secrets/litellm.env` (root:root 0400) | deleted |
| `secrets/providers.env` (sigit:users 0440) | contains `LITELLM_MASTER_KEY` |

Changes to `litellm-podman.nix`:

```nix
# Before
environment = litellm.environment // { DATABASE_URL = "postgresql://litellm:7e6c7...@127.0.0.1:5432/litellm"; };
environmentFiles = lib.optional (litellm.environmentFile != null) litellm.environmentFile;

# After
environment = litellm.environment;
environmentFiles = [ "${appdata}/litellm-podman/database.env" ]
  ++ lib.optional (litellm.environmentFile != null) litellm.environmentFile;
```

The container now reads `DATABASE_URL` from `/srv/appdata/litellm-podman/database.env` (generated by `common/db` on first activation), eliminating the hardcoded password.

### 4.5 Capability filters: CLI-only, not routing

The capability filters (`--text-only`, `--vision`, etc.) are CLI-only filtering against the model inventory. They do not affect LiteLLM's routing - currently LiteLLM only routes text generation (`/v1/chat/completions`). Multi-modal routing (image generation, audio, embeddings) would require:

1. Adding `modalities` field to gateway.json providers
2. Updating `render.sh` to generate modality-specific routing rules
3. A consumer (OpenWebUI or custom HTML) that calls the correct endpoints

## 5. Diagnosis

The trailing-space bug in `providers.env` was insidious: the key worked via direct curl (shell strips trailing whitespace in variable assignment) but failed through LiteLLM (Python reads the env var literally, including the leading space). This was confirmed by inspecting the container's environment:

```bash
sudo podman exec litellm env | grep ZAI
# ZAI_API_KEY= b11ef6d04e9140048babc0200c8b8aae.cC7UuzN19li1JBfO
```

The `DATABASE_URL` hardcoding was a pre-existing issue: `common/db/default.nix` generates a random password and stores it in `database.env`, but `litellm-podman.nix` was ignoring it and using a committed plaintext password instead.

## 9. Recommendations

- Run `litellm-cli providers blacklists` periodically to audit broken models
- Use `litellm-cli models fetch <provider>` to verify model availability before adding providers
- Keep `providers.env` single-sourced for all secrets to avoid dual-file maintenance
- Test new API keys via direct curl before adding to sops (avoids rebuild cycles for invalid keys)
