# Per-Host Identity Overlays (and Finishing a Migration That Wasn't)

**Author:** Codebot

## 1. Objective

Give every host on the three-machine OpenCode fleet its own identity, without touching the shared config. The mechanism is v2's `OPENCODE_CONFIG` overlay: one small JSON file per host carrying `hostname`, `username`, `group`, and whatever else genuinely differs, while `opencode.json` stays byte-identical everywhere.

Along the way, close out a migration that the previous session's report had already declared `done`. It was not done.

## 2. Background

The fleet is Windows native (`Vantage-V14G4`), DebianWSL (`debianWSL`), and FedoraWSL (`fedoraWSL`), all syncing from a hub repo at `C:\Users\SIGIT\git\opencode-v2`. The homelab is deliberately excluded - it runs v1 and is intentionally drifted.

The overlay had a troubled history. It was created 2026-09-26, worked for a few hours, then contributed to a `worktree not found` hard failure and a `500` on startup. The file was deleted, the delta inlined into Windows' live config, and the `OPENCODE_CONFIG` User-scope variable was left dangling. By 2026-09-28 the pattern was retired in favour of a hand-maintained delta, on the reasonable grounds that a single-key difference does not justify a whole file.

Then it turned out the single key could not live in the shared config at all. `npx -y @dguido/google-workspace-mcp` does not work on Windows. Worse, it fails *deceptively*: `opencode mcp list` cheerfully reports `connected` and then real calls die with `MCP error -32000: Connection closed`. Direct `node <abs>/dist/index.js` works. A per-host mechanism is not optional here.

## 3. Problem

Three problems, in ascending order of how much they wanted to ruin the session.

### 3.1 I destroyed a 501-line file

I collapsed `skills/sync-opencode/SKILL.md` to a single line. The cause was piping an array into PowerShell's `Set-Content -NoNewline`, which joins array elements with *nothing* - destroying every newline and fusing adjacent lines into one unreadable rope.

This is the same class of mistake the file's own subject matter warns about, which is a humbling note. Recovery took restoring from `HEAD`, rebuilding, and finally writing a whitespace-blind verifier that could prove the reconstruction was character-exact rather than merely plausible:

```
IDENTICAL - candidate reproduces the original text exactly.
24374 chars (whitespace-stripped) on both sides, 501 lines
```

The lesson, now burned into the workflow: never pipe into `Set-Content -NoNewline`. Use `edit`, or Python with `newline='\n'`.

`2026-09-29-migrate-task-manager-to-plan-manager.md` was written with the confident voice of a job well done. It contains a commit hash, a `git push`, fleet validation tables, and a "False convergence" section reassuring us that the `sync-plan` scripts were already generated by bootstrap.

### 3.3 The distros were still on the old data root

Both WSL distros had `~/.opencode/tasks/` and no `~/.opencode/plan/`. The plugin hardcodes `BASE = path.join(HOME, ".opencode", "plan")`, so any synced plugin would have looked at a directory that did not exist. Silent, total task loss on two of three machines.

## 4. Work Performed

### 4.1 Repaired the corrupted skill file

Restored from `HEAD`, rebuilt to 501 lines, verified character-exact with a whitespace-blind comparator. The collapsed original was *preserved* as `sync-opencode-SKILL-collapsed.txt` - which is the only reason this was recoverable at all, and a lesson worth keeping: when a file is already broken, do not delete your copy of the brokenness.

### 4.2 A2 migration on all three hosts

The user chose **A2** (make `.opencode/plan` a real clone) over **A1** (name-only rename), after reading the journal. That was the right call.

| Host | Result |
|---|---|

The bare repo **keeps the name `opencode-tasks.git`**. Renaming it would mean repointing three peers plus the homelab umbrella for cosmetic gain only; the plugin hardcodes the working *directory*, not the remote filename. The user explicitly ratified this. Cosmetic renames are not free, they are just expensive.

An uncommitted 2026-09-28 revision to one task file was merged into `active/` during the move rather than silently dropped.

### 4.4 Bootstrapped the overlay

`bootstrap-wsl.sh` now generates the overlay from the hostname it just set, validates it parses and carries the right `hostname` **before** pointing anything at it, and exports `OPENCODE_CONFIG` in `~/.bashrc` behind an existence guard. A future distro rebuild needs no hand-editing. This is what distinguishes a reactivated pattern from a re-retired one: the manual step is gone.

### 4.5 Installed overlays on all three hosts

| Host | File | Carries |
|---|---|---|
| Windows | `opencode.windows.json` | identity + `mcp.gws.command` = direct `node` |
| DebianWSL | `opencode.debian.json` | identity only |

One naming convention across the fleet: a trailing `wsl` is stripped, so `debianWSL` -> `opencode.debian.json`, matching `opencode.windows.json`. An earlier run produced `opencode.debianwsl.json`; those leftovers were cleaned up, along with a stale `.bashrc` guard that tested for the deleted filename and so was dead code that looked correct on inspection.

The Windows User-scope variable does **not** leak into WSL - confirmed `0` inherited variables. That was the failure mode I most wanted to rule out, because a Windows path in a Linux env is exactly the dangling `OPENCODE_CONFIG` that caused the original 500.

### 4.6 Restart and verification

The restart is the user's action, not mine - the two `opencode-bin` processes predate the migration, and killing them from inside the session would kill the session. A new PowerShell tab, then three checks that mean something:

| Check | Result |
|---|---|
| `OPENCODE_CONFIG` in the live process | Set, file parses, correct hostname |
| `tasks` tool reads the new data root | 18 tasks; `~/.opencode/tasks` **does not exist**, so it can only be reading `.opencode/plan` |
| A real `gws` tool call | **552 labels returned** |

That third row is the load-bearing one. The shared `opencode.json` uses `npx -y`, which fails on Windows. A successful call through the overlay's `node` command is proof the merge happened - and `opencode mcp list` would have said `connected` either way. The tool lies; the tool *call* does not.

The `tasks` output initially looked alarming - the same 18 tasks with 2026-09-27 dates as before the migration. The dates are per-task fields; `session-index.json` had been rebuilt at 12:23 that day. Untracked by design, rebuilt per host, mtime is the honest signal.

## 5. Diagnosis

The overlay's original failure was never the mechanism. `OPENCODE_CONFIG` is a documented v2 input, and v2 merges only *conflicting* keys, so a partial overlay is safe. What failed was operational hygiene around it: a file deleted while an environment variable still pointed at it, and no verification step that could distinguish "merged" from "started up and produced a plausible-looking `connected`".

That is the theme of this entire session. Every false claim in the previous report, and the corrupted file, and the two distros quietly on the wrong data root, share one root cause: **appearance of success was accepted in place of evidence.** `mcp list` instead of a call. A commit message instead of a commit. A report instead of a directory listing.

## 7. Solution Summary

Per-host identity belongs in per-host files, selected by `OPENCODE_CONFIG`, generated by the bootstrap so the pattern survives a rebuild. The shared config stays byte-identical because the shared config is not where differences go. And every claim of success needs a check that could have failed.

- Backup tray (`reapply_*.py`, `diff_regions.py`, and friends) embeds file content and can be deleted.

## 10. Recommendations

- **Keep the collapsed original.** `sync-opencode-SKILL-collapsed.txt` is the ground truth that made a 488-line loss recoverable. Delete it after the next few sessions, not before.
- **Verification must be able to fail.** If a check cannot come back red, it is not a check. `mcp list` is the canonical example of a check that always passes.
- **A report is not a commit.** Before trusting a `done`, check that the named commit exists (`git log --all --grep`), that the named files exist, and that the claimed invariant holds on every host - not just the one you were working on.
- **Do not pipe into `Set-Content -NoNewline`.** On Windows, in any circumstance, ever. This is the second time this pattern has cost real time.
- **Prefer cosmetic stability to cosmetic renames.** The bare repo keeps `opencode-tasks.git` because the name costs nothing and the rename would cost three repointed peers.
- **If it recurs:** the rollback is cheap. Unset `OPENCODE_CONFIG` and restart. Do not debug around a 500 caused by a dangling overlay.
