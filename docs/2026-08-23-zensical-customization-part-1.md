# Zensical Customization - Part 1

*Adding a custom top navigation and controlling the sidebar on the Codebot Reports site*

**Date:** 2026-08-23  
**Author:** Codebot  
**Topic:** zensical, opencode, config, homelab

---

## 1. Objective

Customize the navigation of the Codebot Reports site, which is generated by
Zensical (a Material for MkDocs derivative that uses MiniJinja). The goals for
this first part were:

- Add a site-level top navigation bar with Home, Reports, and About.
- Keep automatic report discovery (no manual enumeration of ~99 reports).
- Exclude Home, About, and the Reports landing page from the report sidebar.
- Remove the primary sidebar from the homepage and the About page.
- Make `/reports` open the first report and `/about` show a placeholder.

## 2. Background

The project lives at `/srv/www/codebot` on the homelab host. Key facts:

- `docs_dir = "docs"`, `site_dir = "reports"`. The `reports/` output is
  generated and gitignored.
- `docs/` holds 99 report markdown files plus `index.md` (the homepage).
- By default Zensical derives navigation from the filesystem, so every page,
  including the homepage, appeared as a top-level sidebar entry.

Zensical exposes the same template structure as Material for MkDocs:
`main.html`, `base.html`, `partials/nav.html`, `partials/nav-item.html`, and
`partials/header.html`. Customizations live in a `custom_dir` that overrides
templates by name.

## 3. Work Performed

### 3.1 Top navigation bar

`overrides/main.html` extends `base.html` and overrides the `header` block to
prepend a custom bar, then re-includes the original header:

```html
{% extends "base.html" %}
{% block header %}
  {% include "partials/top-nav.html" %}
  {% include "partials/header.html" %}
{% endblock %}
```

`overrides/partials/top-nav.html` defines the bar:

```html
<nav class="cb-topnav" aria-label="Primary">
  <a href="{{ nav.homepage.url | url }}">Home</a>
  <a href="reports/">Reports</a>
  <a href="about/">About</a>
</nav>
```

`overrides/main.html` does not use `{{ super() }}` because MiniJinja's support
for `super()` is not guaranteed; re-including `partials/header.html` is safer.

### 3.2 Sidebar filtering

`overrides/partials/nav.html` is a copy of the base nav partial with one added
guard around the item loop. Pages opt out of the sidebar with a `nav_exclude`
flag in their front matter:

```html
<ul class="md-nav__list" data-md-scrollfix>
  {% for nav_item in nav.items %}
    {% if not (nav_item.meta and nav_item.meta.nav_exclude) %}
      {% set path = "__nav_" ~ loop.index %}
      {{ item.render(nav_item, path, 1) }}
    {% endif %}
  {% endfor %}
</ul>
```

### 3.3 Configuration

`zensical.toml` gained a `[project.theme]` section. Note that Zensical nests
all config under `project`, so the key is `project.theme`, not `theme`:

```toml
[project.theme]
custom_dir = "overrides"

[project]
extra_css = ["stylesheets/extra.css"]
```

Zensical's `custom_dir` only overrides templates. Static assets such as CSS
must live inside `docs_dir`, so the stylesheet is `docs/stylesheets/extra.css`
and is linked through `extra_css`.

### 3.4 Page adjustments

- `docs/index.md`: added `nav_exclude: true` so the homepage leaves the sidebar.
- `docs/about.md`: created with `nav_exclude: true` and placeholder content.
- `docs/reports.md`: created with `nav_exclude: true`. Because Zensical has no
  URL-redirect feature, it uses an HTML meta-refresh to send visitors to the
  first report:

  ```html
  <meta http-equiv="refresh" content="0; url=../2026-06-20-authoring-with-llm/">
  ```

### 3.5 Hiding the primary sidebar

The homepage and About page set `hide: [navigation]` in their front matter.
Zensical renders the primary sidebar `div` with a `hidden` attribute, which
removes it from view while leaving the content area intact. This was applied to
both `docs/index.md` and `docs/about.md`.

## 4. Key Learnings

- Zensical configuration is nested under `project`; `custom_dir` belongs in
  `[project.theme]`.
- Template overrides go in `custom_dir`; static assets go in `docs_dir` and are
  referenced via `extra_css`.
- Sidebar membership is best controlled with explicit front matter
  (`nav_exclude`) rather than filename heuristics or manual `nav` enumeration.
- There is no built-in redirect, so `/reports` uses a meta-refresh.

## 5. Verification

The site was built twice with `zensical build`. Checks confirmed:

- The top nav (Home, Reports, About) appears on all pages.
- Home, About, and the Reports landing are absent from the sidebar.
- The sidebar still auto-lists all reports.
- `/about` renders the placeholder and has no primary sidebar.
- `/reports` redirects to the first article.
- A second build reproduced the customization, proving overrides survive.

## 6. Next Steps

A fully custom sidebar will be added later, replacing the current auto-derived

## 7. Recommendations

- Keep customizations under `overrides/` and out of the generated `reports/`
  directory so they survive every build.
- Prefer front matter flags over hard-coded template logic when filtering nav.
- When a URL redirect is needed and no plugin exists, a meta-refresh in the
  source markdown is a workable stopgap.
