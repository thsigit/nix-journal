# The LiteLLM Gateway Evolution - Part 9

*Consolidate 3-file config into gateway.json*

**Date:** 2026-08-09  
**Author:** Codebot  
**Topic:** LiteLLM, config, refactor, homelab, NixOS  

---

## 1. Objective

Consolidate LiteLLM gateway config from three files (providers.json, router.yaml, models.json) into single gateway.json following opencode.ai ProviderConfig schema pattern.

## 2. Background

Three-file config: providers.json (connections + policy), router.yaml (capability routing), models.json (auto-fetched inventory). Every admin edit touched two files. Every script read three sources. NixOS module wired three file paths, seeded two on activation, watched three for changes.

## 3. Problem

Admin cognitive load. Script complexity. Module wiring overhead.

## 4. Work Performed

### 4.1 Solution: Merge to gateway.json
Merged providers.json and router.yaml into single gateway.json with clean schema:
```json
{
  "providers": {
    "ollama": { "enabled": true, "baseURL": "http://127.0.0.1:11434", "apiKeyEnv": null, "prefix": "ollama", "blacklist": [] },
    "openrouter": { "enabled": true, "baseURL": "https://openrouter.ai/api/v1", "apiKeyEnv": "OPENROUTER_API_KEY", "prefix": "openrouter", "blacklist": ["openai/gpt-4o-mini", "..."] }
  },
  "routing": {
    "aliases": { "local-chat": "ollama/llama3.2", "cloud-chat": "openrouter/openrouter/free" },
    "fallbacks": [ { "ollama/llama3.2": ["openrouter/openrouter/free"] } ]
  }
}
```
models.json stays separate -- auto-generated by daily timer, inventory for litellm-render join.

### 4.2 New Flow
```
models.dev -> fetch-models -> models.json (inventory)
                              |
              gateway.json (admin edits here)
                              |
                 litellm-render -> config.yaml
```
Note: config.yaml is upstream LiteLLM convention (proxy reads via --config /app/config.yaml). We automated it. Admins edit gateway.json (our schema), litellm-render produces upstream-compatible config.yaml.

### 4.3 Updated Scripts
| Script | Before | After |
|--------|--------|-------|
| litellm-render | Reads 3 files | Reads gateway.json + models.json |
| litellm-add-provider | Writes providers.json | Writes gateway.json |
| litellm-disable-provider | Writes providers.json | Writes gateway.json |
| litellm-enable-provider | Writes providers.json | Writes gateway.json |
| litellm-providers | Reads providers.json | Reads gateway.json |
| litellm-missing | Reads providers.json | Reads gateway.json |
| litellm-doctor | Reads providers.json + router.yaml | Reads gateway.json |

### 4.4 NixOS Module Changes
Activation script seeds one file instead of two. Path unit watches gateway.json + models.json instead of three. litellm-render wrapper exports LITELLM_GATEWAY_JSON instead of LITELLM_PROVIDERS_JSON + LITELLM_ROUTER_YAML.

### 4.5 Deleted Files
- providers.json and router.yaml (runtime copies)
- providers-seed.json, router-seed.yaml, models-seed.json (committed seeds)
- gateway-seed.json (new seed, one file instead of two)

### 4.6 Verification
Rendered config.yaml byte-identical to old output: 98 models, 4 aliases, 1 fallback chain. Only difference: comment at top:
```
# Do not edit - derived from gateway.json + models.json
```

## 5. Diagnosis

Schema design matters: following existing pattern (OpenCode ProviderConfig) made new format intuitive. Backward compatibility free: renderer produces identical output. One file means one file to watch: simpler path unit, shorter activation script, single place to look when things break.

## 6. Preliminary Assessment

Consolidation complete. No functional change. Operational simplicity improved.

## 7. Solution Summary

Three files -> one gateway.json. All scripts updated. NixOS module simplified. Seeds reduced from three to one. Output identical.

## 8. Verification Plan

Verify config.yaml renders correctly. Test admin edits propagate. Confirm path unit triggers on gateway.json changes.

## 9. Pending Actions

## 10. Recommendations

Follow existing schemas for new formats. Maintain backward compatibility in renderers. Reduce watched files to minimum. Plan CLI consolidation after config consolidation.
