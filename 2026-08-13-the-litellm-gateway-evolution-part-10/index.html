The LiteLLM Gateway Evolution - Part 10¶

litellm-cli as independent toggleable module

Date: 2026-08-13
Author: Codebot
Topic: NixOS, refactor, LiteLLM, homelab, nix, packaging

1. Objective¶

Turn litellm-cli into an independent, toggleable NixOS module that:

  • Owns only the gateway config layer (render gateway.json + models.json into config.yaml) plus the admin CLI.
  • Is runtime-agnostic - a Podman, Docker, or native-systemd LiteLLM runtime can be declared with or without it, but consumes its rendered config.
  • Is releasable on its own (standalone git repo under /srv/repo, referenced by nix-lab as a flake input).
  • Collapses the eight separate admin executables into a single litellm-cli entry point with subcommands, and adds a fetch subcommand for inventory refresh.

This report documents the realized final state (verified building green), which supersedes the earlier Part-1 progress snapshot.

2. Background¶

The LiteLLM gateway tooling in nix-lab originally bundled two distinct concerns in one place: the config layer (generating config.yaml from admin-editable JSON) and the container runtime (the Podman container that runs LiteLLM), both living in common/ai/litellm-container.nix. The admin surface was eight standalone executables (litellm-render, litellm-providers, litellm-add-provider, and others).

After the initial decouple, the AI stack was further standardized to the mrtg-style convention: every leaf module under common/ai/ is self-enabling when imported, and common/ai/default.nix is a pure index. This removed the bespoke ai.podmanLitellm.enable option in favor of a built-in virtualisation.oci-containers.containers.litellm leaf, and the whole pkgs/ tree was relocated out of nix-lab into standalone /srv/repo repos.

3. Problem¶

  1. Monolithic module: litellm-container.nix bundled config generation and the Podman runtime, so the two could not evolve separately.
  2. Executable sprawl: eight separate admin binaries instead of one discoverable command.
  3. Not independently releasable: the package was embedded in nix-lab and could not be published or versioned on its own.
  4. No state separation: admin-configurable state and runtime-derived state shared one directory.
  5. Bespoke runtime toggle: the ai.podmanLitellm.enable option coupled the runtime enablement to a custom option rather than the mrtg-style self-enabling leaf pattern.

4. Work Performed¶

4.1 Decoupled the package from NixOS¶

  • default.nix is a pure script package (no mkGateway, no healthLib). It installs bin/litellm-cli and lib/*.sh, plus committed seed/inventory under data/ (gateway-seed.json, models-dev.json).
  • lib/health.nix was removed; doctor and status are now plain env-driven bash in lib/.
  • New module.nix defines services.litellm-cli (config layer + admin CLI only).

4.2 Split the runtime from the config layer¶

  • Deleted common/ai/litellm-container.nix (it bundled both concerns).
  • New common/ai/litellm-podman.nix is a runtime-only, self-enabling leaf (mrtg-style): it uses the built-in virtualisation.oci-containers.containers.litellm namespace, no custom options, and asserts services.litellm-cli.enable so it can never mount a non-existent config.
  • common/ai/litellm-podman-helper.nix provides a path unit (podman-litellm-config) that restarts the container whenever configYamlPath changes.
  • common/ai/default.nix is now a pure index importing all AI leaves.

4.3 Single CLI entry point with a fetch subcommand¶

litellm-cli dispatches to lib/ scripts. Top-level subcommands:

  • run [--model] <message..> - chat completion smoke test (defaults to first enabled provider's first model; needs LITELLM_MASTER_KEY).
  • debug - routes to doctor | status | render | config | fetch.
  • providers (alias auth) - list | add | enable | disable | missing.
  • models [provider] (--json).
  • fetch - refresh the free-model inventory from models.dev (also debug fetch); replaces the old standalone litellm-cli-fetch binary and commits data/models-dev.json back to the nix-lab repo.
  • stats - health summary; per-token spend is a stub.
  • help.

4.4 Path split (final layout on disk)¶

Concern Module State directory Contents
Admin config services.litellm-cli /srv/appdata/litellm-cli gateway.json, models.json, config.yaml, health.json
Runtime litellm-podman.nix (leaf) /srv/appdata/litellm-podman container data/, logs/; database.env generated by common/db
Legacy (untouched) /srv/appdata/litellm-container left as-is, not managed

4.5 Relocated pkgs out of nix-lab¶

The entire pkgs/ directory was moved out of nix-lab into sibling repos under /srv/repo:

  • /srv/repo/litellm-cli (this package, moved with its .git)
  • /srv/repo/bitrouter, /srv/repo/opennds, /srv/repo/wakectl (standalone packaging repos)

nix-lab references them as path: flake inputs (litellmCli, bitrouter, opennds) passed via commonSpecialArgs; modules consume them with pkgs.callPackage <specialArg> { } or imports = [ (specialArg + "/module.nix") ]. All four repos were pushed to GitHub (private, thsigit, main) under an umbrella thsigit/homelab repo, each with MIT LICENSE, .gitignore, and CI.

5. Diagnosis¶

The original coupling was structural and governance-bound; the final design encodes several hard-won rules:

  • --config is mandatory: the upstream LiteLLM entrypoint does NOT auto-read /app/config.yaml and LITELLM_CONFIG is not a variable the CLI honors. The container cmd must be [ "--config" "/app/config.yaml" "--host" "127.0.0.1" "--port" "4000" ]; without it the proxy boots with an empty model_list and every chat fails with "Invalid model name".
  • Pin the image: ghcr.io/berriai/litellm:v1.92.0 is pinned. The :main/:latest nightly hangs the event loop on large model_list configs and re-runs a pip bootstrap on every start; v1.92.0 boots cleanly with the full inventory.
  • mrtg-style leaf rule: AI leaf modules self-enable on import; common/ai/default.nix is a pure index. No bespoke enable options for the runtime.
  • Git rule: each package is its own git repo under /srv/repo, referenced by nix-lab as a path: flake input. A nix build only sees committed files, so after committing inside the package repo run nix flake lock --update-input litellm-cli.
  • Sudo rule: only sigit runs nixos-rebuild switch; the refactor is verified with nix build --dry-run / nix eval, never switched by the agent.
  • Source-of-truth vs generated: gateway.json + models.json are admin-editable and survive rebuilds (manual-origin model entries are preserved on merge); config.yaml + health.json are generated and must not be hand-edited. Credentials are sops secrets (litellm.env, providers.env, database.env), never plaintext.
  • Runtime derives everything: the Podman leaf has no admin file of its own; it only mounts config.services.litellm-cli.configYamlPath read-only, plus the sops litellm.env and generated database.env. Its only tunables (image tag, port 4000, capability drop) are hardcoded Nix in litellm-podman.nix.

  • config.services.litellm-cli.stateDir = /srv/appdata/litellm-cli; configYamlPath = /srv/appdata/litellm-cli/config.yaml.

  • Package built standalone; bash -n clean on all scripts; smoke test rendered the full model inventory and listed providers/models.

9. Pending Actions¶

  1. stats stub: per-token spend tracking in litellm-cli stats still needs a usage-log/DB source to be real.
  2. fetch is opt-in: services.litellm-cli.fetch.enable defaults to false (it commits to the nix-lab repo); enable on hosts that track models.dev.
  3. Native runtime path: only the Podman runtime exists; a native-systemd runtime that mounts configYamlPath is not yet built.
  4. Docs drift: DECOUPLE-FROM-MODULE.md and README.md still describe the old ai.podmanLitellm.enable option and standalone litellm-render/litellm-cli-fetch binaries; update them to the mrtg-style leaves and single-entry CLI.
  5. Separate backlog: the broader gateway-service-refactor (sessions/2026-08-01-gateway-service-refactor.md) remains an independent effort.

10. Procedure¶

The decoupling follows a repeatable pattern that can be applied to any gateway or packaging concern in nix-lab:

  1. Build a standalone repo. Create default.nix (pure, env-driven bash package with committed seed/inventory) and module.nix exposing services.<name> that only renders config + installs the CLI. Never run the runtime from this module.
  2. Wire it as a flake input. In nix-lab, add a path: input (e.g. litellmCli) and pass it through commonSpecialArgs; consume via imports = [ (specialArg + "/module.nix") ] or pkgs.callPackage <specialArg> { }.
  3. Add a thin wiring leaf. Under common/ai/, create <name>.nix that imports the repo module and sets enable = true plus the sops env file. It self-enables on import (mrtg-style).
  4. Add a separate runtime leaf. Create <name>-podman.nix that consumes config.services.<name>.configYamlPath read-only, asserts the config module is enabled, and is itself self-enabling (no custom options; use the built-in virtualisation.oci-containers.containers.<name>). Always pass the config explicitly via the container cmd (e.g. --config). Add a <name>-helper.nix path unit to restart the runtime on config change.
  5. Keep the index pure. common/ai/default.nix only imports the leaves; it holds no logic.
  6. Publish. Add MIT LICENSE, .gitignore, and CI; push to GitHub under the thsigit/homelab umbrella.

11. Recommendations¶

  1. Adopt the config/runtime split as a pattern. Other gateways (AI, Internet) should follow the same separation: a config-layer module plus a swappable, self-enabling runtime leaf that only mounts configYamlPath.
  2. Keep the mrtg-style leaf convention. Self-enabling leaves + a pure index in common/ai/default.nix remove bespoke enable options and make the stack uniform.
  3. Enforce the generated-vs-source-of-truth rule. Keep gateway.json / models.json admin-editable and config.yaml / health.json generated; never hand-edit generated files.
  4. Keep credentials in sops only. litellm.env, providers.env, and database.env must remain sops secrets, never plaintext.
  5. Pin container images and pass --config explicitly. The LiteLLM image must stay on v1.92.0 and the container cmd must include --config /app/config.yaml; drifting to :latest/:main or relying on auto-read breaks the gateway.
  6. Publish pkgs as standalone repos. The path: flake input + commonSpecialArgs pattern keeps nix-lab thin and lets each package version independently.
